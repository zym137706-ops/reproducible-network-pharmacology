# Case handoff: what the researcher must provide

The case is **blocked** on the remaining scientific inputs (committed disease extract, manual STP
exports, expected outputs). HGNC, the disease query, the background rule and the PubChem structures
(local only) are prepared.

| # | What | Where | Format | Acceptance check | Blocked step |
|---|---|---|---|---|---|
| 1 | CTD disease extract (query/term/inclusion are recorded; only redistribution permission is missing) | local: `data/local/case/disease_genes.txt`; repository path `examples/demo/inputs/disease_genes.txt` | one HGNC symbol per line, UTF-8; 179 rows, SHA-256 `321e5441…` | `rnp validate` accepts the file; permission to commit it under CTD terms; query/release/date retained | `validate` (disease input), everything downstream |
| 2 | Eight manual SwissTargetPrediction exports | `examples/demo/inputs/stp/quercetin.csv` … `chlorogenic-acid.csv` (names fixed in `compounds.tsv`; pending list in `inputs/STP-PENDING-SUBMISSIONS.tsv`) | native CSV/XLSX export per compound; one file per `stp_file` | `rnp ingest stp` binds all 8 to the explicit `stp_file`; no quarantine/missing; log `STP-SUBMISSION-LOG.tsv` completed with structure/species/date/hash | `ingest stp` → `targets.tsv` |
| 3 | Per-compound submission record | `examples/demo/inputs/STP-SUBMISSION-LOG.tsv` | TSV template; fill every column, including submitted SMILES/InChI, species, date, result file, SHA-256 | no blank required fields; structure/species/date consistent with the actual STP job | `ingest` cannot be called a traceable STP submission |
| 4 | HGNC complete-set snapshot | `examples/demo/inputs/hgnc_map.tsv` (provided) | frozen HGNC-derived table, CC0 | release/date/hash/attribution in `HGNC-SOURCE.md` | **provided/frozen** |
| 5 | Conditional enrichment backgrounds | `examples/demo/inputs/universe-0.10.txt`, `universe-0.05.txt` | one HGNC symbol per line | generated by `scripts/build_case_background.py` from T_r; rule/input hashes recorded; GO effective background and mapping loss recorded by enrich | `enrich` after STP exports exist |
| 6 | Case licence/source evidence | `examples/demo/CASE-FREEZE.yaml` → `data_sources:` | fields present; disease extract still local-only | no fabricated values; restricted sources not committed | acceptance as a public case |

## Submission log template

Use [`inputs/STP-SUBMISSION-LOG.tsv`](inputs/STP-SUBMISSION-LOG.tsv) and the pending list
[`inputs/STP-PENDING-SUBMISSIONS.tsv`](inputs/STP-PENDING-SUBMISSIONS.tsv). The eight rows and
`stp_file` names are prefilled; fill the blank columns:

```text
compound  pubchem_cid  stp_file  submitted_structure  structure_source  species
submitted_date  result_file  retrieved_date  operator  result_sha256  notes
```

`submitted_structure` must be the structure actually submitted (SMILES/InChI), not a guessed one.
`species` must be the actual selection (Homo sapiens is expected by the config). `result_sha256` is
the file hash, not a placeholder.

## After inputs arrive

1. Complete `CASE-FREEZE.yaml`: disease fields, data source licences/hashes, STP log, universe.
2. Run `rnp validate --config examples/demo/run.yaml` and fix only real format/binding errors.
3. Run the full chain **in the verified Linux CI environment**:
   `validate → ingest → intersect → network → enrich → report → manifest --check-inputs`.
4. Create independently checked expected counts/tables and only then mark the case frozen/computed.

Do not automate STP submission and do not commit disease/structure data whose terms are unverified.
